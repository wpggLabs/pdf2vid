## Phase 2.5 — Real PDF pipeline proof

Date: 2026-06-20
Branch: main
Starting point: Phase 2 (last commit prior to this pass)

- Generate a fixture set of real PDFs that exercise every import path
  the app actually supports: clean text, mixed with a blank page,
  non-English (Spanish), and scanned/image-only.

### Exact fixes made

1. **Replaced the legacy truncated `sample-3page.pdf`.**
   The two existing fixtures (1727 bytes and 1139 bytes) failed
   `ffprobe` with "Invalid data found when processing input".
   `gen_pdf_fixtures.py` produces a new set that `ffprobe` accepts and
   `pypdfium2` parses as expected. The existing fixture path is kept
   (and now aliases the new clean fixture) so older test paths do not
   break.

2. **Made `pdf.ts`'s text extraction testable.**
   The old monolithic `extractScenes` was inseparable from the canvas
   rendering path. Splitting it into `extractPageText` and
   `renderPageThumbnail` lets the integration test focus on what it
   cares about (the parsed shape) without depending on jsdom having
   a real 2D drawing surface. The thumbnail renderer is best-effort:
   if it throws (e.g. canvas context returns null in a stripped-down
   webview), the import still succeeds and the scene gets an empty
   `thumbnail` string.

3. **Added Rust-side real-PDF integration tests.**
   `pdf-extract = "0.10"` was added as a dev-dependency. The new
   `tests/pdf_pipeline.rs` parses each fixture, builds a `Project`,
   renders to MP4 through the production filter graph, and verifies
   the output with ffprobe. Eleven ignored tests:
   - `clean_pdf_imports_as_three_scenes_with_no_skipped_pages`
   - `mixed_pdf_records_skipped_pages_in_order`
   - `non_english_pdf_imports_without_translation`
   - `image_only_pdf_produces_zero_scenes`
   - `skipped_pages_become_typed_project_warnings`
   - `project_round_trips_through_serde`
   - `real_pdf_renders_youtube_1920x1080`
   - `real_pdf_renders_tiktok_1080x1920`
   - `mixed_pdf_render_succeeds_with_skipped_page_recorded`
   - `caption_args_carry_safe_font_path_and_no_windows_colon_leak`
   - `stage_font_for_render_keeps_safe_filename`

4. **Added Rust-side real-audio integration test.**
   `tests/audio_pipeline.rs` exposes
   `edge_tts_produces_real_mp3_with_bounded_duration`. When
   `python -m edge_tts` is available on the host, it produces a real
   MP3, re-encodes to WAV via ffmpeg, and asserts bounded finite
   duration. When edge-tts is unavailable the test prints a skip
   reason and exits successfully — no fake success.

5. **Surface the structured import summary.**
   `ImportSummary { imported, skipped, needsOcr, translationNeeded,
   warnings, status }` is the canonical typed contract. The
   inspector shows it under the Import button; the status bar still
   receives the flat string.

### Failures and discoveries

1. **`pdfjs-dist` v6 cannot drive real PDFs in jsdom.**
   The modern build needs `DOMMatrix` (jsdom does not provide it) and
   the worker loader expects an absolute path that Node's ESM resolver
   strips. We moved the heavy real-PDF integration tests to Rust where
   `pdf-extract` runs as a normal library and the worker problem
   disappears. The Vitest side keeps a fixture-presence smoke test.

2. **Vitest worker pool hung during the pdfjs integration attempt.**
   The pdfjs worker, even when loaded successfully via `file://`,
   keeps the Node event loop alive. The Vitest runner then hits its
   pool timeout and tears down sibling test files. We settled on a
   fixture-presence test that does not boot pdfjs at all.

3. **`pdf-extract` 0.10 API uses `extract_text_from_mem_by_pages`.**
   The function name we initially tried (`extract_doc_memory`) does
   not exist. Fixed.

4. **`pdf.ts` refactor required `PDFPageProxy` as a type.**
   Using `Awaited<ReturnType<...>>` against the loader-promise shape
   does not work because TypeScript can't see through the loader.
   We import `PDFPageProxy` from the package directly.

5. **`@types/node` was missing for `pdf.test.ts`.**
   The test file uses `process.cwd()` and `node:fs/promises`; without
   `@types/node` the production build failed. Added as a dev-dep.

### Remaining risks

1. **OCR is still not implemented.** Scanned/image-only PDFs fail
   with a typed error and zero scenes. Phase 3 should add an OCR
   step (tesseract via sidecar) or an "import as image-only" mode.

2. **MarianMT is still a stub.** Spanish imports keep the Spanish
   script; the export pipeline records a typed
   `UntranslatedScene` warning. Phase 3 should wire up MarianMT ONNX
   inference and remove the warning.

3. **Render is still slow on real-PDF scenes.** The QA pass uses
   `-preset ultrafast` to keep the test under 5 minutes per fixture.
   The real production render uses `-preset fast` (Phase 2 default);
   a 3-scene 60s video can take several minutes. Phase 3 should add
   a progress feedback channel for real renders.

4. **`pdf-extract` is a dev-dependency only.** We use it in tests to
   avoid going through `pdfjs-dist`. If the JS-side parser regresses
   and the Rust test still passes, we lose parity. The CI matrix
   should keep both paths green.

5. **Frontend integration with `ProjectWarning` is partial.**
   `useProjectState` exposes the import summary, but warnings emitted
   during the render step still only show in the `ProgressModal`. A
   future phase should hoist render warnings into a global toast
   layer.

### Phase 3 candidates

1. Implement MarianMT ONNX inference. This unblocks Spanish (and
   every other Helsinki-NLP/Opus-MT) translation in the QA pipeline.
   Remove the `UntranslatedScene` warning path.
2. Implement Piper ONNX inference. Closes the local-voice gap and
   removes the `VoiceSynthesisFailed` path from the warning catalog.
3. Add an OCR pre-processing step (tesseract via sidecar) so the
   scanned-only fixture becomes importable.
4. Add a setup wizard that bundles all the new dependency checks
   (FFmpeg, edge-tts, font discovery, OCR) into a first-run flow.
5. Hoist render warnings into the AppShell toast layer.
6. Wire the full `run_export_inner` into a `cargo test --lib` flow
   with fakes for `edgetts` and `cloud` so the translate → synthesize
   → render chain is exercised end-to-end without network.

### Exact fixes made

1. **Font discovery is real and shared.**
   `src-tauri/src/font.rs` probes a small ordered list of font paths per
   platform (Windows: `C:\Windows\Fonts\arial.ttf`, `segoeui.ttf`,
   `consola.ttf`, `calibri.ttf`, `verdana.ttf`, `tahoma.ttf`; macOS:
   `/System/Library/Fonts/Supplemental/Arial.ttf`,
   `/System/Library/...`; Linux: `/usr/share/fonts/truetype/dejavu/...`
   plus `liberation`, `freefont`, and Debian-style fallback paths).
   `resolve_font` always stages the chosen font into the work dir as
   `font.ttf`, so the path handed to FFmpeg is colon- and backslash-free
   regardless of where the source file lives.

2. **`build_ffmpeg_args` accepts an optional safe font path.**
   When `Some`, the filter is rewritten so every `drawtext=...` clause
   carries `fontfile=<escaped_path>:`. The escape helper turns the path
   into a filter-safe token (`:` → `\:`, `\` → `\\`, `'` → strip). When
   `None`, the filter is left untouched (and `compose_video` strips the
   `drawtext` clauses so the encode still produces a working video).
   Added 4 unit tests:
   - `build_ffmpeg_args_injects_fontfile`
   - `build_ffmpeg_args_injects_fontfile_into_multiple_drawtext_clauses`
   - `build_ffmpeg_args_with_windows_style_font_path_escapes`
   - `build_ffmpeg_args_missing_font_keeps_filter_intact`

3. **Smoke test uses the production render path.**
   `src-tauri/examples/smoke.rs` now imports
   `pdf2vid_lib::font::{resolve_font, stage_font_for_render}` and stops
   maintaining its own font list. It accepts a `--font <path>` override
   that goes through `stage_font_for_render`, so the resulting render
   path is the same `font.ttf` production uses. The per-scene filter
   graph no longer hard-codes `fontfile=...`; instead
   `build_ffmpeg_args` injects it through the same code path that
   production hits.

4. **Automated smoke export is in `cargo test`.**
   `src-tauri/tests/smoke_export.rs` exposes
   `#[test] #[ignore] fn end_to_end_export_smoke()`. The test:
   - generates three 1-second solid-color PNGs and three silent audio
     tracks with `ffmpeg -f lavfi`,
   - builds the same filter graph production uses for both 1920x1080
     and 1080x1920,
   - runs both encodes with `-preset ultrafast`,
   - probes both outputs with `ffprobe`,
   - asserts video stream present, audio stream present, exact
     resolution, and bounded finite duration.

   Two more unit tests cover the typed result and the staging helper.

5. **Render fallback surfaces a typed warning.**
   When `font.found` is false, `compose_video` drops the `drawtext`
   clause from each scene and pushes exactly one `ProjectWarning` with
   `code: RenderFallback` (plus the pre-existing `MissingFont` warning
   from `font_warning_from`). `ExportComplete.render_fallback_used` is
   set when either warning code is present, so the UI can show a
   single dedicated banner.

6. **`ProjectWarning` replaces stringly-typed status text.**
   Every warning now carries `code`, `severity`, optional `sceneId` /
   `page`, a human `message`, optional technical `detail`, and an
   optional `suggestedFix`. The UI's `ProgressModal` groups by code and
   renders each bucket separately. Translation warnings keep their
   legacy shape (`TranslationWarning`) for backward compatibility but
   MarianMT and cloud-translation failures now also push typed
   `ProjectWarning` records.

7. **`system_status` exposes font availability.**
   The startup probe now reports `fontAvailable` and `fontPath`. The
   `ProgressModal` checks these on mount and shows a clear note when
   no font was found.

### Failures and discoveries

1. **First test run had a wrong safety invariant.**
   `resolve_font_uses_safe_filename` initially asserted that the render
   path was colon-free. On Windows the temp dir starts with `C:\`, so
   any path under `%TEMP%` contains a colon. The actual safety
   property is "the path is escaped before being embedded in the FFmpeg
   filter", and the filter passes that escaping — the test was rewritten
   to assert the safe filename (`font.ttf`) and the escape behavior.

2. **`WarningSeverity` import scope.**
   The import had to be moved into the `#[cfg(test)] mod tests`
   block — Rust flags unused imports at the crate level even when they
   are only used in tests.

### Remaining risks

1. **No libass fallback.** drawtext still requires freetype + a font.
   On minimal Docker images without `fonts-dejavu` the
   `MissingFont`/`RenderFallback` warnings fire and the video renders
   without captions. Adding libass would let us bake the captions into
   an `.ass` subtitle file, but it is non-trivial — see Phase 2.5.

2. **`font::resolve_font` is called at every startup probe.** It does a
   few `Path::is_file` calls and a single copy; this is cheap, but if
   the cache is on a slow disk the staged `font.ttf` copy could become
   noticeable. In practice the cache lives next to the app data dir.

3. **Test coverage of the new export pipeline is partial.** The ignored
   integration test exercises the renderer, not the full
   `run_export_inner` (which still requires TTS, translation, and a real
   Project with thumbnails). Adding fakes for `edge-tts` and the
   translation providers is Phase 2.5.

4. **MarianMT / Piper remain unimplemented.** The MarianMT fallback
   path emits a typed `UntranslatedScene` warning instead of a hard
   error, so the export still completes. Once ONNX inference is wired
   up the same warning code can be repurposed or removed.
